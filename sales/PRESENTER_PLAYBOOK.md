# Phase 3 presenter playbook

## Before the meeting

- Open the private Next.js demo and the Streamlit fallback in separate tabs.
- Confirm the Y-12 logo and fictional-data notice appear.
- Reset the deterministic scenario.
- Test both tours with narration, captions, and silent mode.
- Test microphone permission; live voice is optional.
- Confirm the browser zoom is 100% and notifications are silenced.
- Keep this playbook and the executive deck available offline.

## Recommended 25-minute meeting

1. Two minutes: frame the purchasing problem and desired outcome.
2. Twelve minutes: run the executive value tour.
3. Six minutes: let Catalyst Guide Live answer questions or use typed fallback.
4. Three minutes: present the founding-partner offer and success measures.
5. Two minutes: agree on the decision path and next meeting.

## Opening

“This is a private Catalyst Innovations demonstration personalized for Y-12 with fictional data. It is not connected to Y-12 systems. I want to show how one procurement record can become easier for employees, more controlled for Finance and Purchasing, and much easier to defend during review.”

## Strong questions to ask

- Which step creates the most rework today?
- Where do approvals most often stall?
- How is available inventory checked before a purchase?
- Which invoice exceptions consume the most AP time?
- What evidence do examiners or internal audit request most often?
- Which three measures would make a 30-day pilot successful?

## Objections

**“AI cannot make purchasing decisions for us.”**
Agreed. Catalyst AI explains and recommends; authorized employees decide. The system preserves the evidence and segregation of duties.

**“We cannot expose member data.”**
Procurement does not need member data. This demo uses fictional records only, and production scope will define strict data boundaries and tenant controls.

**“We already have purchasing software.”**
The question is not whether transactions can be entered. It is how much manual work, preventable spend, exception investigation, and audit preparation remains around those transactions.

**“What happens if the AI or internet fails?”**
The core demo and both tours have deterministic fallbacks. No financial workflow depends on live voice.

**“Is this production-ready today?”**
This is a sales demonstration. The paid pilot validates workflows, controls, integrations, security requirements, and production scope before implementation.

## Backup procedure

1. If live voice fails, say: “The live concierge is optional; I’ll continue with the presentation-safe guide.”
2. If the Next.js deployment fails, open the Streamlit backup.
3. If both hosted demos fail, present the executive deck and use the scripted featured scenario.
4. Do not debug credentials, DNS, or infrastructure in front of the prospect.

## Close

“If this direction fits the problem you want to solve, the next step is a $2,500 30-day founding-partner pilot. That fee applies to the $7,500 implementation. We will agree on three measurable outcomes, validate the workflow with your team, and define the production scope together.”
